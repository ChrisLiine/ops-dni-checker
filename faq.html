How does the landing page checker work?

The checker reads your uploaded CSV, adds a gclid query param(if one is not already present) to spoof a Google Ads visitor, randomizes the order of each landing page URL, and lists them to be checked. The checker will then create multiple chrome browsers with multiple tabs at a time in the cloud to visit each landing page url. The checker will wait 10 seonds after visiting a page in order to provide the page enough time to load all elements. After waiting 10 seconds, the chcker will scan the page. If a number is found in a phone number format (visible, not visible, within a script, a fax number, within the body, etc) the checker will return this number in the results.

Once all sites have loaded and the phone number detection has been completed, the checker will search these numbers against the Liine tracking number database to see if any of the numbers are registered tracking numbers. If a number is found to as a registered tracking number, the checker will note this in the results. Once the results are complete, an email will be sent to the email address provided in the CSV with a link to download the results CSV.

Why is the same site listed multiple times?

By now you have noticed that some landing pages are listed multiple times within your results CSV. This is because the report is designed to list phone numbers, and not landing pages. Each line within the report is a number that was found while the landing page checker was scanning the sites. Some sites may have multiple different phone number listings on the same page, and thus will be listed multiple times within the results. For example, if a practice has two locations listed on the same landing page, the checker will find both numbers, and list both numbers within the results CSV while displaying the same landing page url since both numbers were found on the same page.

Not yet. We're building a similiar site that will allow customers to upload their own CSVs directly. The difference in the sites will be less required fields for the CSV upload, and less detailed results.

How many files can I upload at a time?

Each upload can only consist of one CSV file. However, you can upload as many times as you'd like. Each file will be processed separately, so you should receive separate emails for each upload.

What if I upload the same file twice or two uploads for the same customer?

If you've uploaded the same file twice on accident, there is no need to worry! The system will automatically handle duplicate uploads. The second submission will overwrite the first submission. So if you made a mistake in your first upload, simply re-upload the corrected CSV and the system will process the new file instead.

I just uploaded my CSV, when will I get my results?

The processing time depends on when your file has been uploaded. All landing page uploads are processed in the order they are received at the beginning of the hour. For example, if you upload your file at 1:15pm, your file will be processed at 2:00pm. If you upload your file at 1:55pm, your file will be processed at 2:00pm as well. Once your file is being processed, the time it takes to complete depends on how many landing pages are in your upload.

What does 'x' column mean?

Below are each of the columns definitions found in the results CSV. Please note while only scrape one columns are listed below, scrape two columns will have the same definitions:

  • account_name: The name of the account associated with the landing page (pulled directly from your CSV upload).
  • account_id: The CRS ID associated with the landing page (pulled directly from your CSV upload).
  • cleaned_lp: This is the URL that the landing page checker is told to navigate to on browser/tab creation. The URL may be adjusted so the web protocol used is "https", and a gclid is applied to the checked page.
  • swapping_status: This status will report either true or false. True lets the user know the numbers have swapped by comparing the scraped phone numbers from scrape one and two. This could consists of swapping from any third party.
  • scrape_one_num: This is a phone number that was found during the scrape.
  • scrape_one_label: If the phone number found during the scrape is a Liine tracking number, this column will contain the name of said number within Liine.
  • scrape_one_desc: If the phone number found during the scrape is a Liine tracking number, this column will contain the description associated with said Liine tracking number.
  • scrape_one_crs_id: If the phone number found during the scrape is a Liine tracking number, this column will contain the CRS ID of the customer this tracking number is associated with. Please note, this CRS ID can differ from the provided CRS ID within the CSV upload.
  • scrape_one_swap_number: This column will either be true or false. If the scraped number is contained within a pools swap over numbers list, the result will be true.
  • scrape_one_run_id: The run ID is a unique eight digit ID generated per browser instance. One browser can check up to five landing pages, so multiple landing pages may contain the same ID.
  • scrape_one_network_idle: During the page scrape, one of the check points consists of checking if the network has idled. This means there have been no ongoing network requests within 500ms. If there have been none, than the returned status will be true. 'false' is a common result. We will wait a maximum of five seconds before no longer checking for network requests.
  • scrape_one_body_visible: After checking if the network has idled, the next check is to look for the body element. If the body element does not exist within eight seconds, this column will return false.
  • scrape_one_date_scanned: This column will list the date and time(24 hour format) the website was checked.
  • scrape_one_metadata: If the number found is a Liine tracking number, this column will list the metadata associated with said number.
  • scrape_one_obs_results: If a known OBS vendor is found on the site (please view the list of known obs vendors here), the checker will list the vendor and check if the vendor link includes our session guid.
  • scrape_one_final_url: The "final url" is url of the page captured immediately before the phone numbers are pulled from the website. This can differ from the "cleaned lp". This is usually caused by 301/302 redirects, but can sometimes be due to website scripts that remove query parameters before page load.
  • scrape_one_liine_guid: If a page has our Liine code installed in any way (via gtm, lazy loaded, cached, or direct) and has loaded, this field will contain the session guid created for this 'visitor'.
  • scrape_one_liine_iframe: This field will either contain true or false. If a Liine jotform iFrame container is found on the page, the field will contain true.
  • scrape_one_hidden_input: This field will either be true or false. If a non Liine iFrame form was found on the page, the form contents will be scanned for our standard guid injection check (placeholder = liine_guid_ph).
  • scrape_one_input_injection: This field will either be true or false. If the hidden input field was found, the checker will scan the field to see if a value that matches the Liine guid exists.
  • scrape_one_hardcoded_num: The Liine checker will attempt to scrape a website with Javascript and without JS. This field will contain the number found when Javascript was disabled.
  • scrape_one_form_present: This field will either be true or false. If a non Liine jotform form is found on the site (glacial form, one two three form, or a generic form builder) this field will contain true. Please note, if a form is found anywhere on this page (even a newsletter subscription form) the field will be true.
  • liine_swap: This field will either be true or false. If number swapping was detected, the checker will then confirm if one of the swapped numbers belongs to Liine. If the numbers swapped with a Liine tracking number, the field will be true.
  • redirect_status: This feed will either be true or false. This feed will compare the "cleaned landing page" (the url the checker is told to navigate to) and the "final url" (the url of the page grabbed immediately before the page is checked). If the urls do not match, then the status will be true (a redirect has occurred).
  • form_issue: If a non Liine form is present, the checker will look for the hidden input field and a value within this field. If a hidden input is found with no value or if a form is found with no hidden input field, the checker will return true(there is an issue) with the issue description
